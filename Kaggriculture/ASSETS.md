## Actual cleanup

The October 2 cleanup already removed 324,493 listed disposable/generated files:
**107,091,570,859 logical bytes**. Available filesystem space increased by
**40,422,789,120 bytes** during that operation. Its receipt and reconstruction
records are retained; this work was not repeated.

The October 3 organization moved seven sibling directories intact; it deleted no
files. During this October 22 closeout, only the three abandoned `.venv` directories
inside those historical audit clones were removed. The source, Git objects,
reports, test fixtures, `uv.lock`, `pyproject.toml` and Python-version files
were hash-checked and preserved. Installed package versions and reconstruction
instructions were saved first. Rebuilding those old environments requires the
saved requirements and externally available packages; it is not an offline
wheel archive. The main working environment was not removed.

| Measurement | Before this closeout cleanup | After cleanup and report preparation |
|---|---:|---:|
| Workspace allocated-byte traversal (`du`) | 132,838,346,752 | 129,012,862,976 |
| Historical local archive (`du`) | 3,924,131,840 | 73,363,456 |
| Removed environment logical file bytes | — | **3,684,735,150** |
| Observed filesystem available-space increase during deletion | — | **9,326,592** |

These quantities are intentionally separate. Btrfs compression/shared extents,
external hardlinks and concurrent writes mean neither logical bytes nor a
workspace `du` decrease is exclusive physical reclaim. Shared package caches
were not deleted to inflate the reclaim figure. No unique source, final output,
checkpoint or original replay was deleted in this closeout.

Research remains paused. The old monitor was already stopped; the final-result
read for this report was one-shot. No new submission, recurring job or experiment
is required to reproduce the delivered archive.
